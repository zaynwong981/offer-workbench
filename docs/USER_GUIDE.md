# OfferWorkbench 使用文档

把求职偏好、岗位资料、匹配依据、定向简历、PDF 和跟进记录放在一个系统里。无需调用聊天模型即可完成日常整理。当前是适合个人使用的 0.8.0 本地工具，不是多用户招聘平台。支持定向简历、岗位跟进、日历与薪酬测算，变更见 [CHANGELOG.md](CHANGELOG.md)。

开发／迁移从 **[PROJECT.md](PROJECT.md)** 开始。体验示例见 [合成演示](docs/DEMO.md)，发布与数据恢复见 [版本与回滚](docs/RELEASING.md)。



## 日常使用

1. 打开 `http://127.0.0.1:8766/career`，在「偏好与设置」维护城市、方向、薪资和排除公司等条件。
2. 「找岗位」点击搜索 BOSS，或手动粘贴岗位 JD。搜索只在点击时发生，一次一页，不后台轮询。
3. 点开岗位后会自动保存浏览记录；用分栏读详情、查看匹配依据，记下稍后考虑或不考虑及原因。分数是规则关键词覆盖率，不能代替资历、校招资格或录用判断。
4. 选择已有简历作为底稿，创建岗位专属副本，进入简历编辑页微调。副本复制真实经历，不自动编造业绩或改写工作事实；再次进入同一岗位的专属版本会继续编辑，不重复创建。编辑后点击「返回当前机会」回到对应机会详情。
5. 导出 PDF。工作台把文件直接保存到配置目录，文件名附时间戳，预览不落盘。
6. 在岗位的「准备投递」保存沟通文字、作品链接和提交入口。去原渠道自行提交后，回来选择实际使用的PDF、渠道及时间，勾选确认。系统才会记录本次投递，并保留当时的简历与岗位快照；导出不会自动投递。
7. 在求职页备份机会与偏好，在简历页备份简历与照片。两类备份彼此独立，恢复简历后再恢复机会便于保留关联。求职备份只包含已保存记录，导出前请先保存未完成的偏好和跟进修改。

工作流：偏好 → 搜索/手动 JD → 匹配证据 → 收藏 → 简历副本 → 编辑/导出 → 原页面沟通 → 跟进/面试/复盘。

## 浏览、筛选与收录岗位

宽屏左侧列表、右侧详情；小屏点开详情后可关闭返回。当前标签页保留筛选、选中岗位、滚动和准备草稿。关闭标签页前保存准备内容，浏览器暂存不能代替备份。

「本次筛选与已存方案」把条件分为必须满足、优先考虑、愿意探索。排序先看必要条件冲突数，再看偏好和探索命中数；同分维持原顺序。缺失信息、薪资区间部分重叠会留待核实，不直接隐藏。可展开岗位中的判断依据核对原条件。方案最多50个，应用后不会自动搜索，也不会修改已保存的全局偏好。

「稍后考虑」「不考虑」表达你的取舍，可以改回「继续了解」。招聘方未通过属于招聘进度，另行记录；一次不考虑不会屏蔽整家公司。

手动收录时粘贴JD或岗位链接即可，公司、薪资与地点可后补。来源可选招聘网站、公司官网、朋友推荐等；工作台只保存文字与链接，不自动访问或解析外部页面。

## 准备材料与确认投递

在岗位详情切到「准备投递」，选择已有简历直接导出，或复制专属版本后微调。保存沟通文字、作品链接及提交入口；复制文字、打开网页、导出PDF都不会发送或投递。

本人实际提交后，从该岗位的导出记录中选择对应PDF，先打开核对，再填写渠道与北京时间并确认。已确认记录在「跟进与留档」中，可重新打开当时的PDF。后来修改简历、岗位或删除简历版本不会改写留档。旧版“已投递”状态没有历史文件的，会明确显示缺少留档，不用现在的简历补造。

岗位导出单份PDF上限5MB；本机全部留档（含编码、简历与岗位快照）共40MB。留档满时先保存完整求职及简历备份；可删除无需保留、尚无投递确认的机会及其留档，已确认机会只能归档，不能删除。归档不会释放留档空间；暂未提供自动清理。简历工作台直接导出的PDF不关联岗位，也不会自动出现在岗位留档中。

## 素材与AI

在求职工作台打开「素材与AI」。素材分经历、项目、成果；来源可以是记录名称、日期或核验说明。标记已核实前需填写来源。也可从现有简历取一个段落，确认表单后保存。素材最多1000条，AI草稿最多100份；到上限时先备份再整理。

AI设置提供 OpenAI、Anthropic、DeepSeek 与自定义兼容接口。填写服务商为你的账号开放的模型 ID、Base URL 和密钥，启用并保存。保存不联网；「预览连接测试」只准备固定测试文字，核对后勾选才能发送。[查看配置与接口说明](reference/AI_PROVIDERS.md)。

日常使用：选择任务 → 选择JD／素材／单个简历段落 → 查看完整发送预览 → 核对接收方及费用确认 → 发送。模型输出保留为草稿；润色和压缩可对照原文手动微调，勾选事实核实后，只替换所选段落。撤销仅在该段落未再次修改时可用，不覆盖其他编辑。提炼与推荐列出原句供你判断，不自动整篇重写。

密钥不回显、不进入浏览器存储、求职备份或升级快照。发送不会自动附带姓名、照片、整份简历和其他岗位；所选正文中的个人信息仍由你检查。失败保留发送正文与可用的原始输出，不自动重试；可复制草稿到其他工具处理。所有事实、数字与职责范围仍需本人核实，程序无法证明语义真实。

「JD需求统计」选择最多100个已保存岗位，按本地词表及补充词统计，每个词在同一JD最多计一次。没有正文的岗位不计分母；可展开每个词查看岗位原句与记录时间。它描述这批样本，不代表招聘市场。

## 简历版本、保存与导出

侧栏可搜索名称，筛选正在使用、方向母版、岗位草稿、归档或全部，最多500份。旧简历默认按方向母版展示；岗位专属副本标为岗位草稿。归档可恢复，不出现在岗位版本选择或批量导出中；既有实际投递留档不变。

编辑后点击保存才写入本机。浏览器草稿和已保存文件不同，离开前留意保存状态。「保存并用素材与AI准备」会先保存再跳转。个人资料、照片和教育经历由各版本共用；经历正文与排版属于所选版本。

预览不生成导出文件。导出会保存到已配置目录，并在文件名加入时间戳保留历史；批量导出仅处理未归档版本。可在排版设置提高最低字号（9–12pt）；自动适配不会突破这个下限，放不下一页时保留多页，由你删减内容。

求职备份升级为v4，包含已保存素材与AI草稿，仍可导入v1–v3。旧备份不含新内容，导入前先备份当前资料。恢复的AI草稿仅供参考，不恢复发送授权或直接采纳能力；需要重新预览。API配置和密钥需另行配置。

## 调整工作区

左侧菜单顶部按钮可收起或展开导航；收起后用图标切换，悬停或键盘聚焦可识别名称。两工作台各自记忆展开状态，布局只保存在当前浏览器。窄屏菜单改为横向排列。

简历编辑与 PDF 预览在宽屏可同时显示。拖动中间分隔线改变宽度；聚焦分隔线后用左右键微调，Home／End 调至宽度边界，Enter 或双击恢复均分。编辑区至少 320px、预览区至少 300px；窄屏保留原有编辑／预览切换。PDF 排版字号不随编辑器缩放改变。


## 薪酬与个税

北京医保参考方案含每月 3 元固定附加额；上海基本公积金为 5%／6%／7%，补充缴存须单位开通后另填 1%–5%，默认不缴补充，分别按元取整。杭州社保基数及公积金参考值包含转载来源；失业个人费率暂采用 1%（税务答复降费政策已于 2025 年底到期，未确认延续），请按单位实际新政策核实并在高级参数中修正。杭州大病保险从医保个人账户划扣，不重复减银行卡到手。

偏好城市保留北上广深杭＋远程；勾选「其它」后可填写中国大陆城市或香港，用逗号分隔。旧城市仍保留，删除文字并保存才会移除。远程是本地偏好，搜索时另选城市；区县、办公楼请填在办公地点，未知城市不会被当作全国搜索。香港薪资币种需核实，五城人民币个税估算不适用于香港。

岗位方向与希望接触的业务可按「大类 → 具体方向 → 加入」选择，也可在下方直接修改、删除或补充匹配词。常用薪资区间与手填金额相互同步，0表示不限；办公地点为空时显示通用填写示例，已有地点不自动覆盖。

招聘类别提供「不限／校招／社招／实习」。校招使用应届条件，社招使用非在校／应届经验条件；实习使用CLI原生实习岗位筛选，可同时限定在校生。不是切换校招专区，也不保证报名资格，仍需核实岗位原文。矛盾的经验或岗位类型会在执行前提示调整。

在「找岗位」展开「从已保存偏好填写」，选择一个城市、岗位方向和业务，再点「填写搜索条件」。只填入条件，不会自动搜索；目录内业务使用行业筛选，自定义业务词并入关键词。一次一组，不批量遍历。手填薪资没有平台对应区间时不扩大范围，旧10–15K方案执行前需重新选择。[查看筛选依据](reference/BOSS_FILTER_SOURCES.md)。

在「薪酬与个税」输入税前月薪、发薪月数、奖金和每月专项附加扣除；选择北京、上海、广州、深圳或杭州，查看全年到手、月均到手、个人社保/公积金与逐月累计预扣税。也可在岗位详情点击「测算这个岗位的税后收入」：明确月薪可带入，范围薪资需要自行选择上下限，年薪/日薪/面议不自动推算。

- 城市差异来自缴费参数，居民工资个税税表全国统一。预设是已核验的政策快照，适用时间和官方来源可在页面展开，详细依据见 [SALARY_POLICY_SOURCES.md](reference/SALARY_POLICY_SOURCES.md)。公积金5%是可修改的试算值，不代表公司承诺比例。
- 这是固定参数下全年12个月、同一雇主、居民工资薪金的 Offer 情景估算，**不是2026年历史逐月工资条**。各险种基数不同，实际申报工资不一定等于新 Offer 月薪；高级参数可按实际税前允许扣除部分调整。
- 额外薪月与额外奖金默认12月发放并入工资。只有符合全年一次性奖金条件、且当年尚未使用该方式时，才可选单独计税；同时提供两种方案比较，不因税额更低就自动替用户选择资格。现行单独计税政策执行至2027年末。
- 专项附加扣除填写个税 App 已申报的每月合计；它减少应税额，不是从到手工资再次扣除。实际换工作、工资浮动、补缴情形、其他综合所得、税收减免和年度汇算退补税未建模。
- 到手收入扣除个人缴费，不包括单位缴费或公积金账户到账额；公积金账户金额不等于当月可支配现金。
- 参数仅保存在当前浏览器本机，与简历/求职备份分开。计算在浏览器完成，不向招聘平台或第三方发送薪资、扣除信息。更换浏览器或清理站点数据后需重新填写。

## 操作时的保存与返回

- **偏好与跟进草稿**：在本浏览器标签页暂存，切换页签或刷新后可继续；这不等于写入本机数据库。匹配仍使用已保存的偏好。关闭标签页前请点击「保存偏好」或「保存跟进」。浏览器存储被清理、标签页被关闭或恢复失败时，不保证草稿仍在。
- **搜索**：保留本标签页的条件和已取回结果。请求过程中可切页，返回结果不会把你强行切回搜索页；刷新页面不会自动重新查询。正在请求、失败和本页无结果分别提示。
- **岗位资料**：「修改岗位资料」可清空旧薪资、地址等字段。留空代表信息缺失，不会继续显示原值；修改只作用于本机记录。
- **简历关联**：关联版本已删除或不存在时会明确提示，要求重新选择；不会默默改用另一份简历导出。
- **版本导航**：简历选择同步到页面地址，刷新后保持当前版本。版本较多时侧栏列表独立滚动，底部导出与备份按钮保持可见。

## 快速启动

先下载 [GitHub Release](https://github.com/zaynwong981/offer-workbench/releases) 中的源码包并解压，或克隆：

```sh
git clone https://github.com/zaynwong981/offer-workbench.git
cd offer-workbench
```

需要 Python 3.11+。建议创建虚拟环境：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python server.py --open
```

macOS 也可双击 `打开简历工作台.command`。Windows 运行 `python -m venv .venv`、`.venv\Scripts\python -m pip install -r requirements.txt`，然后双击 `start.bat`。Linux 可使用上述命令。

macOS 自动使用系统黑体；Windows 尝试微软雅黑。Linux 可安装 `fonts-wqy-zenhei`。其他字体通过 `CAREER_FONT_REGULAR` / `CAREER_FONT_BOLD` 指向可嵌入中文 TrueType `.ttf` 或 `.ttc`，字体许可由使用者确认；不打包操作系统字体。Windows/Linux CI 配置已提供，是否通过以实际 CI 记录为准。

服务固定只监听 `127.0.0.1`。默认端口 8766，可用 `--port 8767`。打开页面后没有账号注册、云同步或模型密钥设置。

## PDF 保存位置

默认 `exports/`。可将 `config.example.json` 复制为 `config.local.json`，修改 `exportDir`；也支持 `CAREER_EXPORT_DIR` 或 `--export-dir`。配置文件相对路径以项目目录解析。个人部署可保留自己的绝对路径，公开源码不要包含 `config.local.json`。

运行数据默认在 `data/`，可用 `--data-dir` 指定独立目录。

## BOSS 连接与排障

可选依赖：[boss-agent-cli](https://github.com/can4hou6joeng4/boss-agent-cli)，本适配器按 **3.0.1** 的 JSON schema 验证。未安装或未登录也能完整使用手动 JD、简历、匹配和看板。

当前已收到真实第 1 页岗位返回，但第 2 页和部分关键词的薪资完整性尚未通过在线验收。网页能正常使用不等于 CLI 接口可用；平台返回风险时会停止读取。

```sh
uv tool install --python 3.12 'boss-agent-cli==3.0.1'
```

工作台只开放 `search` / `detail` 两项读能力，调用时复用你手动启动、已登录的 CDP Chrome。不会自动导入浏览器凭据、启动登录、发送消息、上传附件或批量投递。每次手动搜索使用 `--no-cache` 跳过 CLI 的 24 小时搜索缓存，避免会话恢复后仍显示旧的空页或缺薪资结果；不会自动重试或补抓详情。CLI 自身仍可能写入本机搜索缓存。它不是 BOSS 官方开放 API，上游页面与风控策略变化会影响可用性。

macOS 可双击 `连接BOSS浏览器.command`，或运行下列命令启动专用浏览器：

```sh
open -na 'Google Chrome' --args --remote-debugging-address=127.0.0.1 --remote-debugging-port=9222 --user-data-dir="$HOME/.career-studio-chrome" 'https://www.zhipin.com/'
```

Windows 在命令提示符运行（按实际 Chrome 安装路径调整）：

```bat
"%ProgramFiles%\Google\Chrome\Application\chrome.exe" --remote-debugging-address=127.0.0.1 --remote-debugging-port=9222 --user-data-dir="%LOCALAPPDATA%\career-studio-chrome" https://www.zhipin.com/
```

Linux 使用 `google-chrome --remote-debugging-address=127.0.0.1 --remote-debugging-port=9222 --user-data-dir="$HOME/.career-studio-chrome" https://www.zhipin.com/`。

在该窗口本人完成登录，保留 BOSS 标签页和浏览器，再回到工作台搜索。CLI 默认探测本机 9222；可在启动工作台前设置 `CAREER_BOSS_CDP_URL=http://127.0.0.1:9222`。不要把调试端口对外开放，结束使用可关闭专用浏览器。

- **检测到 CLI ≠ 已登录。** 登录有效性只能由实际读取验证。普通 `boss login` 生成存储会话并不保证此浏览器模式可用。
- 找不到 CLI：确认 `boss --version`，或设置 `CAREER_BOSS_BIN` 为可执行文件路径。
- `AUTH_REQUIRED` / `BROWSER_SESSION_NOT_FOUND`：检查上述专用浏览器是否运行、BOSS 是否已登录，再手动重试。
- `ACCOUNT_RISK` 等：系统停止后续读取，不自动重试或清除风险锁；在官方页面人工处理后，遵循上游恢复方式。
- 请求超时：单次最多约 45 秒，停止后可手动重试；一个工作台同时只执行一项 BOSS 请求。
- 详情标识失效：重新搜索并保存同一职位，岗位详情以最新读取为准。
- 页面筛选覆盖的是已取回结果。多城市、多岗位探索需逐个搜索；并非全站穷尽采集。薪资下限、办公楼、拒绝名单等在本地解释，不保证平台本身支持该过滤。

## 匹配与产品边界

匹配从 JD 识别能力词组，在每版简历正文中找证据，同时核对城市、月薪范围、排除公司和过往拒绝情况；缺资料标为待核实。命中同一主题不等于掌握全部同义技能。工资按能识别的税前月薪 K 范围比较，年薪、面议、额外薪数和福利需人工核对。

当前不包含：LLM 自动改写、考试代答、后台自动监控、对外消息发送、附件投递回执、企业招聘端、多用户权限、云部署。界面中的求职状态与面试备注由本人维护，不会因一次导出或访问岗位而冒充投递成功。岗位页面的精确地址、真实性、是否仍招、校招届别资格，仍以平台和招聘方确认结果为准。

## 数据与恢复

求职备份v3包含筛选方案、准备内容、日程、实际PDF及简历和岗位快照，可能比旧版大，请妥善保存在本机。导入请求最大64MB。仍可恢复v1/v2备份，但旧备份没有的新数据会被替换为空；导入前先备份当前内容。恢复时检查文件哈希、快照和关联关系，任何校验失败都不替换现有记录。简历当前可编辑版本仍需单独备份。

旧版本代码不能安全写入新版留档数据库。回滚必须从升级前快照恢复到新目录，见发布与回滚文档。


- `data/resumes.json`：当前简历、照片、版本。
- `data/history/`：简历保存前快照。
- `data/career.sqlite3`：偏好、筛选方案、机会、日程、准备内容、PDF留档与投递记录。
- `config.local.json`：个人导出目录，不进入发布包。
- `exports/` 或自定义目录：PDF 和批量 ZIP。

简历编辑器发现未保存草稿时，会先锁定编辑、复制、导入和导出，避免其他操作覆盖草稿。同一版本的草稿可直接恢复编辑；若草稿版本与本机不同，需先下载包含姓名、照片、教育和全部简历的完整草稿备份，再明确确认是否整份替换。替换前会下载本机内容的备份，服务器也保留保存前快照；不会自动合并两个窗口的修改。若选择放弃尚未备份的草稿，会再次提示确认。

简历草稿的浏览器恢复副本与求职页的标签页草稿不是同一类数据。不要把任何浏览器暂存当作正式备份。多个窗口同时编辑时，系统会检查简历版本冲突，并避免一窗口保存时误删另一窗口的草稿；建议完成当前窗口保存后再换窗口。

本地数据没有应用层加密。使用系统磁盘加密和自己的系统账号保护数据。没有遥测；只有本人点击 BOSS 读取时由 CLI 接入平台。备份含个人信息，不应公开。

### 搜索空页与缺失薪资

- 空页只能表示本次没有取回岗位，不能证明没有匹配机会。尤其前一页提示有更多、下一页为空时，应先在专用 Chrome 核对相同条件。
- 薪资为空显示“未读取到薪资”，不替换为面议或推测数字；整页缺薪资会给出明确说明。
- 跳过缓存只保证本次调用 CLI 读取接口，不保证平台返回完整信息，也不会解除平台风险。
- 遇到 `ENVIRONMENT_RISK`，请停止重试，在官方页面确认恢复后再显式解除本地风险锁。网页恢复但接口仍被拦截时，保留风险锁，暂停接口验证。


### 网页正常但平台风险停止

“网页可用”不保证 CLI 的接口请求通过检查；平台拒绝请求后，CLI 本地风险锁和工作台当前进程的停止状态会继续阻止读取。错误本身不足以确认账号封禁或 CLI 缺陷。

请先在专用 Chrome 手动核对相同关键词、城市、下一页和薪资。仅在官方目标页面恢复后，显式执行 `boss clean --risk-lock`，然后停止并重新启动工作台服务，再验证一页。命令清除本地锁并可能清理 CLI 过期缓存，不解除服务器限制；若再次返回风险，应立即停止，不反复清锁。

《BOSS 连接说明》的“网页正常，为什么仍提示平台风险停止？”已提供完整步骤、版本核对和上游问题反馈入口。2026-11-21 的接口仍返回 ENVIRONMENT_RISK，第 2 页与 AI 岗位薪资在线验收尚未完成。

## 求职日历

求职侧栏的「求职日历」支持月历＋当月／单日议程。可新建面试、笔试、截止时间、跟进、Offer 回复和入职事件，也可从岗位详情进入该岗位的日历。每个岗位可关联多项事件，支持编辑、完成、取消和删除。

时间统一为北京时间 UTC+08:00，精确到分钟。面试／笔试等需要开始和结束；DDL 与 Offer 回复只填截止时刻。仅知日期请勾选“具体时刻待确认”，系统不猜时间、不计算精确冲突。重叠事件和落入活动中的 DDL 分别提示，可保留冲突安排；结束时刻恰好等于另一项开始不算冲突。删除岗位会同时删除其关联日程，删除前请备份。

求职备份 v2 含日程，可读取旧 v1；恢复旧备份会恢复到不含日程的状态，先导出当前备份。原下一步日期保留在日历下方，可补充成日程，再按需清空旧日期。ICS 导出为全部日程快照，不是实时同步；网页关闭后无后台通知。
